## Project Overview

Caffee is a macOS Vietnamese Input Method Editor (IME) - a native keyboard input system for typing Vietnamese with diacritical marks. It supports Telex and VNI input methods with app-specific input mode memory.

**Target**: macOS 14+ Sonoma
**Language**: Swift
**Frameworks**: AppKit, SwiftUI

## Build Commands

```bash
# Build
xcodebuild build -scheme Caffee

# Run tests
xcodebuild test -scheme Caffee

# Code formatting (swift-format must be installed)
brew install swift-format
# Formatting runs automatically as a build phase
```

## Architecture

### Data Flow
```
Keyboard Event → EventHook (CGEvent tap) → InputProcessor
    → Engine (Telex/VNI) → TiengViet.transform() → EventSimulator
```

### Key Components

**App/** - Application lifecycle and state
- `AppState.swift` - `@MainActor @Observable` state container: enabled state, typing method, engine options, event-tap health. Creating one has no side effects; `start()` registers the hotkey and the frontmost-app observer
- `AppModeStore.swift` - Pure value type for per-app memory (last mode, pinned mode, sending-strategy override), persisted through `Defaults`
- `PermissionMonitor.swift` - The one Accessibility-trust poller (`AppState.permission`); views and the app delegate react to it instead of running their own timers
- `AutomationService.swift` - `caffee://mode/vi|en|toggle`, `caffee://method/telex|vni` and the control file `~/Library/Application Support/Caffee/switch`
- `Diagnostics.swift` - Plain-text report for bug reports (Settings > Nâng cao)
- `InputProcessor.swift` - Main keyboard event handler that maintains word state and delegates to the typing engine
- `Setting.swift` - Persistent settings using Defaults framework

**Engine/** - Vietnamese typing logic
- `TiengViet.swift` - Core Vietnamese syllable model with tone marks (DauThanh) and diacritics (DauMu). Handles consonant clusters, vowels, and text transformation. Case variants of every cluster are generated by `caseVariants(of:)`
- `EngineConfig.swift` - Immutable engine options (foreign consonants, tone placement, spelling check). Every `TiengVietState` carries its config; there is no global mutable engine state
- `Telex.swift` / `VNI.swift` - Input method implementations following TypingMethod protocol

**Platform/** - macOS system interaction
- `EventHook.swift` - Global CGEvent tap for keyboard interception (requires Accessibility permission)
- `KeyEventPoster.swift` - Instance (one shared by `InputProcessor` and `EventHook`) that simulates backspace and text input to replace typed text. Every posted event is tagged (`syntheticEventTag`) so the tap ignores it, and async strategies run on one serial queue; `EventHook` re-posts real keys behind pending output to keep ordering
- `ReplacementSender.swift` - `Replacement` (delete N, insert text) and the `ReplacementSender` protocol
- `FileMonitor.swift` - Watches one small control file and reports its full contents on every change
- `Focused.swift` - Accessibility API to detect focused elements

**KeyLayout/** - Keyboard mapping
- `KeyboardUS.swift` - US key code map, used only as a fallback; the real character comes from the system (`KeyboardInputEvent.character`) so non-US layouts and the numpad work
- `Keys.swift` - TaskKey enum for special keys (Enter, Tab, Space, arrows)

### Dependencies (Swift Packages)
- **Defaults** - UserDefaults wrapper
- **KeyboardShortcuts** - Shortcut recording/binding
- **LaunchAtLogin** - Auto-start functionality
- **Settings** - SwiftUI preferences window

## Conventions

- The event tap callback must return the system-owned event with `Unmanaged.passUnretained`, never `passRetained`. Tests that call `EventHook.handleEvent` must keep their `CGEvent`s alive.
- Any key that is not a text character or Backspace must reset the word buffer (`InputProcessor`).
- Per-app strategy overrides (`SendingStrategyOverride`) beat the built-in `sendingConfigs`.
- Engine options go through `EngineConfig`, never through globals. `InputProcessor.changeEngineConfig` starts a fresh word.
- The project builds in Swift 6 language mode with clean strict concurrency: UI/state/tap classes are `@MainActor`; the C tap callback re-enters isolation with `MainActor.assumeIsolated`.
- Tests that touch `Defaults` must restore the value (the test bundle is hosted in the real app, so it shares the user's settings).
- Test failure text is hidden by `xcodebuild`'s console output; read it from the newest `.xcresult` (`xcrun xcresulttool get test-results tests --path …`).
- The format build phase runs `swift-format` on every build, so files can change on disk after building.
- Audit notes, status of every item and remaining ideas live in `big-audit.md`.

## Vietnamese Linguistics Reference

**Telex keys**: s=sắc, f=huyền, r=hỏi, x=ngã, j=nặng, aa=â, oo=ô, ee=ê, aw=ă, ow=ơ, uw=ư, dd=đ

**VNI keys**: 1=sắc, 2=huyền, 3=hỏi, 4=ngã, 5=nặng, 6=circumflex, 7=horn, 8=breve, 9=đ
